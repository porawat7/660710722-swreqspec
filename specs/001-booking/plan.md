# แผนทางเทคนิค: จองคิวตรวจสุขภาพ (Booking)

## 1. สรุปแนวทาง
1. ผู้รับบริการที่ผ่านการยืนยันตัวตนแล้วเลือกแพ็กเกจ วัน และช่วงเวลาตรวจสุขภาพ (FR-BKG-01, FR-BKG-06)
2. ระบบใช้ผลยืนยันตัวตนเพื่อค้นข้อมูลจาก HIS ด้วยเลขบัตรประชาชน และอ้างอิงผู้รับบริการภายในด้วย HN โดยไม่เก็บเลขบัตรประชาชนในรายการจอง (IF-IDP-01, IF-HIS-01)
3. ระบบตรวจสอบคิวเดิมและจำนวนที่นั่งก่อนบันทึกการจอง พร้อมออกหมายเลขคิวตามกติกาที่กำหนด (FR-BKG-02, FR-BKG-04, ASM-03, ASM-04)
4. การบันทึกการจองและการตัดที่นั่งต้องป้องกันการจองเกินเมื่อมีการยืนยันพร้อมกัน โดยรายละเอียดจะรอคำตอบ Q-03 (FR-BKG-03, FR-BKG-04)
5. หลังบันทึกการจอง ระบบส่งคำขอแจ้งเตือนแบบ asynchronous และจัดการ retry ตาม FR-BKG-05/NFR-REL-02 (IF-NOT-01)

## 2. เทคโนโลยีที่ใช้
| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| MySQL | CON-TECH-01 | ฐานข้อมูลหลักของการจอง โควตา และ audit log |
| React (Vite) | ทีมเลือกเอง ไม่ได้มาจาก spec | หน้าจอเลือกแพ็กเกจ วัน และช่วงเวลา รวมสถานะสีเทาของช่วงที่ไม่ว่าง (FR-BKG-01, FR-BKG-06) |
| Python FastAPI | ทีมเลือกเอง ไม่ได้มาจาก spec | API สำหรับค้นหาช่วงเวลา ตรวจสิทธิ์ และสร้างการจอง (FR-BKG-01 ถึง FR-BKG-06) |
| TLS 1.2 ขึ้นไป | NFR-SEC-01 | ใช้กับการรับส่งข้อมูลการจอง |
| Worker/คิวงาน asynchronous | IF-NOT-01, NFR-REL-02 | ส่งข้อความโดยไม่ทำให้การจองรอผล และ retry 3 ครั้งภายใน 10 นาที |

## 3. โมเดลข้อมูล
| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| `Booking` | `id`, `hn`, `package_id`, `booking_date`, `time_slot_id`, `queue_number`, `status`, `created_at` | FR-BKG-02, FR-BKG-04, FR-BKG-05 |
| `TimeSlot` | `id`, `package_id`, `slot_date`, `start_time`, `end_time`, `capacity`, `remaining_seats`, `status` | FR-BKG-01, FR-BKG-03, FR-BKG-06 |
| `Package` | `id`, `name`, `status` | FR-BKG-01, FR-BKG-06 |
| `NotificationJob` | `id`, `booking_id`, `channel`, `attempt_count`, `next_attempt_at`, `status` | FR-BKG-04, FR-BKG-05, NFR-REL-02 |
| `AuditLog` | `id`, `accessor_id`, `accessed_at`, `hn`, `resource` | DOM-PDPA-01, AC-BKG-06 |

`Booking` ต้องไม่มีฟิลด์เลขบัตรประชาชนตาม IF-HIS-01 โดยใช้ `hn` เป็นตัวอ้างอิงภายในเท่านั้น

## 4. API / หน้าจอ
- `GET /booking/availability?package_id&from&to` — รับแพ็กเกจและช่วงวันที่ ส่งคืนช่วงเวลาภายใน 30 วัน จำนวนที่นั่งคงเหลือ และสถานะที่ไม่ว่างเพื่อแสดงสีเทา/กดไม่ได้ (FR-BKG-01)
- หน้าจอ `BookingSelection` — เลือกแพ็กเกจ วัน และช่วงเวลา พร้อมคำนวณรายการช่วงเวลาใหม่เมื่อเปลี่ยนแพ็กเกจ (FR-BKG-06; รายละเอียดกฎรอ Q-04)
- `POST /bookings` — รับ `package_id`, `booking_date`, `time_slot_id` และ context จากผลยืนยันตัวตน ส่งคืนหมายเลขคิวหรือเหตุผลปฏิเสธพร้อมหมายเลขคิวเดิม (FR-BKG-02, FR-BKG-04; เงื่อนไขพร้อมกันรอ Q-03)
- หน้าจอ `BookingResult` — แสดงหมายเลขคิวและสถานะการจองเมื่อบันทึกสำเร็จ (FR-BKG-04, FR-BKG-05)
- หน้าจอ `BookingConflict` — แจ้งช่วงเวลาเต็มและแสดงตัวเลือกใกล้เคียง 3 รายการ โดยเกณฑ์การเลือกต้องรอ Q-01 (FR-BKG-03)
- งานเบื้องหลัง `NotificationDeliveryWorker` — ประมวลผล `NotificationJob` แบบ asynchronous และ retry 3 ครั้งภายใน 10 นาที (IF-NOT-01, FR-BKG-05, NFR-REL-02)

## 5. ตารางตรวจ Constraints
| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| CON-TECH-01 | MySQL และโมเดลข้อมูลในหัวข้อ 2–3 | ใช้แล้ว |
| DOM-PDPA-01 | Entity `AuditLog` และการบันทึกทุกครั้งที่เข้าถึงข้อมูลในหัวข้อ 3 และ 7 | ใช้แล้ว |
| IF-IDP-01 | ตรวจผลยืนยันตัวตนก่อนเรียกข้อมูลผู้รับบริการใน API `POST /bookings` | ใช้แล้ว (กรณี IDP ไม่ตอบหรือผลไม่ถูกต้องรอ Q-05) |
| IF-HIS-01 | ค้น HIS ด้วยเลขบัตรประชาชนจากผลยืนยันตัวตน ใช้ HN ใน `Booking` และไม่เก็บเลขบัตรประชาชนในหัวข้อ 3 | ใช้แล้ว (กรณี HIS ไม่ตอบ/ค้นไม่พบ/ข้อมูลไม่ถูกต้องรอ Q-05) |
| IF-NOT-01 | `NotificationDeliveryWorker` และ `NotificationJob` แบบ asynchronous ในหัวข้อ 2–4 | ใช้แล้ว |
| NFR-SEC-01 | TLS 1.2 ขึ้นไปในหัวข้อ 2 | ใช้แล้ว |
| NFR-PERF-01 | ทดสอบ endpoint ค้นหาช่วงเวลาโดยมีผู้ใช้พร้อมกัน 200 คนในหัวข้อ 6 | ใช้แล้ว |
| NFR-REL-02 | retry 3 ครั้งภายใน 10 นาทีใน `NotificationJob` และ worker | ใช้แล้ว |
| NFR-USE-01 | ทดสอบ flow ตั้งแต่เลือกข้อมูลถึงแสดงหมายเลขคิวในหัวข้อ 6 | ยังไม่ได้ใช้ เพราะจุดเริ่ม/สิ้นสุด 3 นาทีรอ Q-02 |

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-BKG-01 | `test_AC_BKG_01_successful_booking` | เตรียมช่วง 09.00 น. เหลือ 1 ที่ ยืนยันการจอง ตรวจว่าบันทึกสำเร็จ มีหมายเลขคิว และเหลือ 0 ที่ |
| AC-BKG-02 | `test_AC_BKG_02_duplicate_unused_booking` | เตรียมคิวที่ยืนยันแล้วแต่ยังไม่เข้ารับบริการในวันเดียวกัน ตรวจว่าการจองใหม่ถูกปฏิเสธและคืนหมายเลขคิวเดิม (ASM-03) |
| AC-BKG-03 | `test_AC_BKG_03_slot_filled_during_confirmation` | จำลองผู้ใช้อีกคนตัดที่นั่งก่อนยืนยัน ตรวจข้อความช่วงเวลาเต็ม ตัวเลือก 3 รายการ และไม่เกิดรายการจองซ้อน |

หมายเหตุ: FR-BKG-06 ยังไม่มี AC ที่อ้างถึงโดยตรงใน spec จึงไม่เพิ่ม test ID ใหม่ใน plan

## 7. ลำดับงาน
1. ออกแบบ schema `Booking`, `TimeSlot`, `Package`, `NotificationJob` และ `AuditLog` โดยไม่เก็บเลขบัตรประชาชน (FR-BKG-01, FR-BKG-04, IF-HIS-01, DOM-PDPA-01)
2. สร้างการตรวจผลยืนยันตัวตนและการอ่านข้อมูลจาก HIS ตามเส้นทางสำเร็จ โดยยังไม่สร้างการจัดการข้อผิดพลาดที่ต้องตัดสินใจจาก Q-05 (IF-IDP-01, IF-HIS-01)
3. สร้าง API และหน้าจอค้นหาช่วงเวลาภายใน 30 วัน พร้อมแสดงช่วงที่ไม่ว่างเป็นสีเทาและกดไม่ได้ (FR-BKG-01)
4. เพิ่มการกรองช่วงเวลาตามแพ็กเกจและโครงหน้าจอเปลี่ยนแพ็กเกจ โดยยังไม่ล็อกกฎที่รอ Q-04 (FR-BKG-06)
5. เพิ่มการตรวจคิวเดิมและการออกหมายเลขคิวแบบรีเซ็ตรายวันตามลำดับการยืนยันสำเร็จ (FR-BKG-02, ASM-03, ASM-04)
6. ทำ flow บันทึกการจอง/ตัดที่นั่ง/ออกหมายเลขคิวให้สอดคล้องกัน และล็อกขอบเขตการทำงานพร้อมกันหลังได้คำตอบ Q-03 (FR-BKG-03, FR-BKG-04)
7. สร้าง worker แจ้งเตือนแบบ asynchronous และ retry 3 ครั้งภายใน 10 นาที (FR-BKG-05, IF-NOT-01, NFR-REL-02)
8. เพิ่ม audit log, TLS และการทดสอบตาม AC ทั้ง 6 ข้อ รวม performance 200 ผู้ใช้พร้อมกัน (DOM-PDPA-01, NFR-SEC-01, NFR-PERF-01, AC-BKG-01 ถึง AC-BKG-06)

## 8. สิ่งที่ยังไม่ทำ
- Q-01 “ช่วงเวลาใกล้เคียง” นับเฉพาะวันเดียวกัน หรือรวมวันถัดไปด้วย? -> ถามพยาบาลคัดกรอง  
  ส่วนที่เกี่ยวข้องกับการจัดลำดับและเลือกตัวเลือก 3 รายการจะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-02 “ยืนยันภายใน 3 นาที” เริ่มและสิ้นสุดการจับเวลาเมื่อใด? -> ถามทีมเอง  
  ส่วนที่เกี่ยวข้องกับตัวจับเวลาและการทดสอบ NFR-USE-01 จะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-03 การจองพร้อมกันต้องรับประกันอย่างไรไม่ให้เกินจำนวนที่นั่ง? -> ถามทีมเอง  
  ส่วนที่เกี่ยวข้องกับกติกาและกลไกป้องกันการจองซ้อนจะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-04 เปลี่ยนแพ็กเกจแล้วคำนวณช่วงเวลาว่างจากกฎใด และรักษาวัน/เวลาเดิมหรือไม่? -> ถามผู้ดูแลตารางคิว/โควตา  
  ส่วนที่เกี่ยวข้องกับกฎการคำนวณใหม่จะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-05 หาก IDP หรือ HIS ไม่ตอบสนอง ค้นไม่พบ หรือข้อมูลไม่ถูกต้อง ต้องดำเนินการอย่างไร? -> ถามผู้ดูแล IDP/HIS  
  ส่วนที่เกี่ยวข้องกับการจัดการข้อผิดพลาดของ IDP/HIS จะยังไม่สร้างจนกว่าจะได้คำตอบ
